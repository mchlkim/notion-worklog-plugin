# 1. 계획

## 목표
무엇을 이루려는 작업인지 한두 문장으로.

## 범위 / 범위 밖
이번에 건드리는 것과 일부러 건드리지 않는 것.

## 접근 방법
어떤 순서로 어떻게 할 것인지.

## 리스크 & 롤백 방안
잘못됐을 때 무엇이 깨지고 어떻게 되돌리는지.

# 2. 실행

- (타임스탬프) 무엇을 왜 했는지, 중간에 바꾼 판단

# 3. 결과

## 검증 방법과 결과
무엇으로 확인했고 어떻게 나왔는지. 명령과 출력을 그대로.

## 남은 일 / 후속 조치
이번에 끝내지 못한 것과 다음에 할 것.

# 4. 개선점

- 이 프로젝트에서 무엇을 고쳐야 같은 일이 반복되지 않는가
- 반복된 함정 / 매번 헤매는 지점 / 문서·설정에 없어서 물어봐야 했던 것
- 감상이 아니라 다음에 실행할 수 있는 형태로 쓴다

# 5. 출처

- 참고한 문서·스펙 (제목 — URL)
- 근거로 삼은 사내 문서 / 이전 카드

# 6. 산출물

- 생성·변경한 파일 (경로)
- PR / 커밋 / 배포된 리소스
