`notion-worklog-skill` 의 보드를 점검한다. 인자가 있으면 그 `프로젝트`로 한정한다.

## 점검 항목

`notion-query-data-sources` 로 칸반 DB를 조회해 다음을 찾는다.

1. **방치된 진행중** — `상태` 가 `계획`/`진행중` 인데 `수정일시` 가 3일 이상 지난 카드
2. **확인 대기 적체** — `상태=검증` 이 7일 이상인 카드 (사람 확인이 밀린 것)
3. **빈 필수 속성** — `세션ID` 또는 `프로젝트` 가 빈 카드, 커밋이 있는데 `푸시` 미체크인 카드
   (`푸시` 는 해당 레포에서 `git branch -r --contains` 로 실제 확인 후 체크해 준다)
4. **미해결 방치** — `미해결` 체크된 카드 중 후속 카드(`관련 작업`)가 연결되지 않은 것
5. **개선점 반복** — 같은 프로젝트 카드들의 `4. 개선점` 에서 반복되는 지적.
   **3회 이상이면 그것 자체를 새 작업(Backlog 카드)으로 만들자고 제안**한다
6. **프로젝트 노트 낡음** — 해당 프로젝트의 최근 카드보다 노트의 `최종 갱신` 이 오래된 것

## 출력

- 항목별로 해당 카드를 표로 보여준다 (ID · 작업명 · 근거)
- 바로 고칠 수 있는 것(푸시 체크, 노트 환류)은 **사용자 확인 후** 고친다
- 카드 생성·상태 변경 같은 조치는 제안만 하고 임의로 하지 않는다
- 점검 결과 자체는 카드로 만들지 않는다 (읽기 전용 점검). 단, 점검에서 나온
  후속 작업을 사용자가 승인하면 그 작업의 카드를 만든다
